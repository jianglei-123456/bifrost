# 03 统一认证

> 目标：AES-GCM 口令加密、初始账号、Spring Security 双入口认证（/api/** 与 /rest/**）。依据：《通用功能说明》§8；《整体技术架构》§7；《音乐管理技术设计》§9；ADR-0003；Subsonic_API_参考 §2（认证公式）。
> 完成标准：hurl 认证场景（成功/失败/双格式/错误码）通过；口令不明文落库/日志；`/api/ping` 与 `/rest/ping.view`（免认证端点）可用。

## T3.1 AES-GCM 口令加密组件

- 加密：随机 12 字节 IV 前置密文（IV + ciphertext）；
- 密钥：环境变量 `BIFROST_AUTH_SECRET`（32 字节）优先；缺失 → 自动生成随机密钥写 `data/secret.key`（权限 600，Windows 下尽力而为）并输出警告日志；
- 解密失败 → 视为认证失败（不抛堆栈到响应）。

## T3.2 初始账号初始化

- 首次启动：按 `bifrost.auth.initial-username`（默认 admin）创建管理员，密码来自环境变量 `BIFROST_AUTH_INITIAL_PASSWORD`（缺失 → 明确报错提示配置）；
- 已存在则忽略；后续以数据库为准。

## T3.3 Spring Security 配置

- 引入 `spring-boot-starter-security`（ADR-0003）；
- 无状态会话（STATELESS）、禁用 CSRF；
- 两条过滤器链：`/rest/**`（自定义认证过滤器）与 `/api/**`（HTTP Basic + t/s 令牌）；
- `/api/ping` 放行；`getOpenSubsonicExtensions`（/rest）免认证放行。

## T3.4 Subsonic 认证过滤器（/rest/**）

- 解析参数 u/t/s/p/v/c/f（URL 编码校验）；
- 认证成功条件（二选一）：`t`+`s` 令牌 = `md5(解密口令 + salt)`（UTF-8 小写 hex，`MessageDigest.isEqual` 恒定时间比较）；或 `p` 明文（`enc:` 前缀先 hex 解码）；
- 失败响应：**HTTP 200** + `status="failed"` + `<error code="40" message="Wrong username or password"/>`（不区分用户不存在/密码错误）；
- 缺 v/c/u → error 10；同时提供冲突认证参数（如 apiKey 与 u/p/t/s）→ error 43；收到 apiKey（未实现）→ error 42；
- 容忍 DSub 附加的 `Authorization` 头（忽略）；
- 认证成功后将用户/客户端名注入请求上下文（nowPlaying 的 playerId 用 `c` 参数，Q20）。

## T3.5 管理 REST 认证（/api/**）

- HTTP Basic（用户名:密码）或 t/s 令牌（与 Subsonic 同款，同一账号）；
- 失败：**HTTP 401** + 信封 `{code:1002, message:...}`；
- 密码永不明文落库/日志。

## T3.6 账号 API

- `GET /api/user`：返回当前账号信息；
- `PUT /api/user/password`：修改密码（校验旧密码，AES-GCM 重加密存储）。
