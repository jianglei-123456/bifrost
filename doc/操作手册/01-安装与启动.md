## 1. 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| JDK | **Java 21** | 需已安装并配置 `JAVA_HOME` |
| 构建 | Maven（推荐用仓库自带 `mvnw` 包装器，自动下载指定版本） | 首次构建需联网拉依赖 |
| 操作系统 | Windows / Linux / macOS 均可 | 本文以 Windows 与 Linux 双示例 |
| 磁盘 | 音乐库所在盘 + 数据目录（默认 `./data`） | SQLite 库与封面缓存都在数据目录 |

> 端口：默认监听 `18080`（`server.port`）。如需改端口，改 `bifrost-bootstrap/src/main/resources/application.yml` 的 `server.port`。

## 2. 构建

在仓库根目录执行：

```bash
./mvnw clean verify        # 完整构建（含单元 + 集成测试）
```

- 只想快速启动跳过测试：`./mvnw -pl bifrost-bootstrap -am package -DskipTests`
- 构建产物：`bifrost-bootstrap/target/*.jar`（fat jar，可直接 `java -jar` 运行）。

## 3. 首次启动（必须设置初始密码）

**第一次启动必须通过环境变量注入初始管理员密码**（不落配置文件、不进仓库，见《通用功能说明》§2.3）：

```bash
# Linux / macOS
BIFROST_AUTH_INITIAL_PASSWORD=你的密码 ./mvnw -pl bifrost-bootstrap -am spring-boot:run

# Windows PowerShell
$env:BIFROST_AUTH_INITIAL_PASSWORD="你的密码"
./mvnw -pl bifrost-bootstrap -am spring-boot:run

# Windows CMD
set BIFROST_AUTH_INITIAL_PASSWORD=你的密码
mvnw -pl bifrost-bootstrap -am spring-boot:run
```

或直接运行构建出的 jar：

```bash
BIFROST_AUTH_INITIAL_PASSWORD=你的密码 java -jar bifrost-bootstrap/target/bifrost-bootstrap-*.jar
```

要点：

- 初始密码**仅首次启动时写入数据库**（AES-GCM 加密存储），之后以数据库为准——后续启动不设该变量也照常运行。
- 若第一次启动时忘记设置，密码不会写入数据库，客户端将无法认证（见 [03-常见问题](03-常见问题.md) §3 的兜底方案）。
- 口令加密主密钥：优先环境变量 `BIFROST_AUTH_SECRET`；未设置则自动生成并写入数据目录 `secret.key`（生产环境建议显式配置，见《通用功能说明》§2.3）。

## 4. 启动验证

应用启动后（默认 `http://localhost:18080`），两个探针：

```bash
# 管理探针 → 返回 pong
curl http://localhost:18080/api/ping

# Subsonic 探针 → 返回 status="ok"（u=用户名, p=密码）
curl "http://localhost:18080/rest/ping.view?u=admin&p=你的密码&v=1.16.1&c=test"
```

## 5. 配置音乐库并扫描

### 5.1 方式一：配置文件（`application.yml`）

```yaml
bifrost:
  library:
    roots:
      - name: 我的音乐        # 音乐目录名称（即客户端看到的 musicFolder 名）
        path: D:\Music        # 音乐目录绝对路径
        enabled: true
      - name: 无损老唱片
        path: E:\Lossless
```

改完配置需重启应用。

### 5.2 方式二：管理 REST（无需重启）

```bash
# 新增音乐目录（管理 REST 用 HTTP Basic 认证）
curl -u admin:你的密码 -H "Content-Type: application/json" \
  -d '{"name":"我的音乐","path":"D:\\Music","enabled":true}' \
  http://localhost:18080/api/music-roots

# 查看音乐目录列表
curl -u admin:你的密码 http://localhost:18080/api/music-roots

# 触发全量扫描（同步阻塞，返回最终统计）
curl -u admin:你的密码 -X POST http://localhost:18080/api/music-roots/scan/all

# 查看扫描状态
curl -u admin:你的密码 http://localhost:18080/api/music-roots/scan/status
```

> Windows 路径中的反斜杠在 JSON 中需写成 `\\`。

### 5.3 扫描说明

- 扫描解析 MP3 / FLAC / M4A 标签，构建"艺术家 / 专辑 / 曲目"索引，支持中文拼音首字母分组。
- 增量扫描：指纹（路径+大小+修改时间）不变的文件会跳过，重复触发安全（幂等）。
- 定时扫描尚未接线（`bifrost.scan.cron` 已声明但无调度实现），当前只能手动触发——管理端 `POST /api/music-roots/scan/all` 或 Subsonic 的 `startScan`；定时扫描待增补。
- 无标签的 WAV 也能入库播放，但不参与艺术家/专辑聚合。

> 本节讲的是**音乐**目录（`/api/music-roots`）。**电子书（EPUB/PDF）图书目录走独立的 `/api/book-roots`**，建目录、扫描、连接阅读器的完整操作见 [04-连接阅读器客户端](04-连接阅读器客户端.md) §1。

## 6. 修改密码

```bash
# 修改管理员密码（校验旧密码）
curl -u admin:旧密码 -X PUT -H "Content-Type: application/json" \
  -d '{"oldPassword":"旧密码","newPassword":"新密码"}' \
  http://localhost:18080/api/user/password
```

改完后**所有客户端需用新密码重新连接**（令牌认证会随之失效）。

## 7. 停止与备份

- **停止**：前台运行按 `Ctrl+C`；后台运行结束对应进程即可。
- **数据目录**（默认 `./data`，可用 `bifrost.db.path` / `bifrost.media.cover-cache-dir` 调整）：
  - `bifrost.db` —— SQLite 数据库（媒体索引、账号、歌单、收藏/评分）
  - `covers/` —— 封面缩略图缓存
  - `secret.key` —— 口令加密主密钥（若自动生成）
- **备份 = 复制整个 `./data` 目录**。恢复时将备份拷回即可，无需其他操作。
- **升级**：停服 → 备份 `./data` → 用新版本启动（schema 自动演进 `ddl-auto=update`，建议备份后升级）。

## 8. 对外暴露（可选）

- 局域网内其他设备连接：用主机局域网 IP 而非 `localhost`，并放行防火墙 18080 端口。
- 公网访问：建议经反向代理启用 **HTTPS**（Nginx / Caddy），Subsonic 明文密码传输才有保障；地址变为 `https://你的域名/rest`。
- Docker 部署规划见《整体技术架构》§9.1（M1 延期交付，代码稳定后提供镜像）。
