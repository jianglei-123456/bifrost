## 1. 排查顺序（先看这条）

遇到任何"连不上"问题，按顺序自查：

1. **服务在跑吗**（Bifrost 机器上）：`curl http://localhost:18080/api/ping` → `pong`？
2. **端口通吗**（客户端设备上）：浏览器打开 `http://192.168.1.10:18080/api/ping` 有结果？
3. **认证对吗**：`curl "http://localhost:18080/rest/ping.view?u=admin&p=你的密码&v=1.16.1&c=test"` → `status="ok"`？
4. **客户端字段对吗**：对照 [02](02-连接Subsonic客户端.md) §4 的填写清单。

第 1、2 步不过 → 看 §2；第 3 步不过 → 看 §3；只有第 4 步不过 → 看 [02](02-连接Subsonic客户端.md) §2/§4。**电子书 / OPDS（阅读器连不上、404、书库为空）问题直接看 §10。**

## 2. 连不上 / 超时 / 拒绝连接

| 现象 | 原因与处理 |
| --- | --- |
| 本机能访问，手机/其它设备不行 | 地址用了 `localhost`（指设备自己）；改填 Bifrost 主机局域网 IP（[02](02-连接Subsonic客户端.md) §2.1） |
| 局域网内也无法访问 | ① 防火墙未放行 18080 端口；② Bifrost 只监听了回环地址——确认应用配置的是 `0.0.0.0` 或未限制绑定地址；③ 路由器 AP 隔离（访客网络） |
| 端口不通但应用在跑 | `server.port` 被改过；或 Docker/反向代理映射了别的端口（见 §8） |
| 能打开但一直转圈 | 地址填到了具体端点（如 `/rest/ping.view`）导致 404；只填到主机:端口（[02](02-连接Subsonic客户端.md) §2.2） |

## 3. 认证失败（error 40）

Subsonic 认证失败统一返回 `status="failed"` + `error code="40"`（协议特性，非 HTTP 401）。

| 原因 | 处理 |
| --- | --- |
| 用户名/密码拼写错误 | 用户名默认 `admin`；密码为初始密码（[01](01-安装与启动.md) §3） |
| **首次启动没设初始密码** | 未注入 `BIFROST_AUTH_INITIAL_PASSWORD` 时密码不会写入数据库，任何密码都失败。兜底见下方"密码忘记" |
| 改过密码后客户端仍用旧密码 | 所有客户端用新密码重连（[01](01-安装与启动.md) §6） |
| 密码含特殊字符被 URL 转义破坏 | 客户端应自行 URL 编码；排查时用 curl 的 `--data-urlencode` |

**密码忘记（含首次未设置）兜底**：v1 无找回机制。若数据目录可牺牲，删除数据目录（默认 `./data`）后重新启动并设置初始密码——**注意：媒体索引、歌单、收藏、评分全部重置**，需重新扫描（音乐文件本身不受影响）。操作前先备份（[01](01-安装与启动.md) §7）。

## 4. 客户端报"未实现 / error 0"

Bifrost 按《音乐管理功能说明》§8.2 能力矩阵实现端点，未实现端点返回 `error code="0"`（如 Sharing/Podcast、Jukebox、转码相关）。**这不是配置错误**。列表中的"⏳ 可增强"项在后续版本逐步补齐。歌词说明：`getLyrics`/`getLyricsBySongId` 已实现，数据来自**音频文件内嵌歌词标签**（USLT/©lyr/Vorbis）；文件无内嵌歌词则客户端显示"无歌词"，在线歌词源（LRCLIB 等）未接入。

## 5. 能连上但看不到音乐 / 列表为空

1. 音乐目录是否配置且启用：`curl -u admin:密码 http://localhost:18080/api/music-roots`（[01](01-安装与启动.md) §5.2）。
2. 是否扫描过：触发 `POST /api/music-roots/scan/all`（同步，返回最终统计）后查看 `GET /api/music-roots/scan/status`；新加文件需重新扫描（增量，很快）。
3. **重新同步曲库（全量重扫）**：改了标签/想回填歌词等新字段时，触发 `POST /api/music-roots/scan/all?fullScan=true`（或单个音乐目录 `POST /api/music-roots/{id}/scan?fullScan=true`；Subsonic 端点为 `startScan` 加 `fullScan=true` 参数）。fullScan 会忽略指纹、逐文件重读标签；常规增量扫描只在文件大小/修改时间变化时重读。
   - **fullScan 还会彻底删除已消失文件的记录**（连带清理歌单条目、书签、播放队列引用）；而增量扫描只是把缺失曲目标记隐藏、保留记录。**注意**：若外置盘临时离线，请勿触发 fullScan（会把该盘曲目从库中清掉，歌单引用一并移除，不可逆）。
4. 文件格式：仅 MP3 / FLAC / M4A 参与索引聚合；WAV 可播不入聚合；WMA/APE 不支持。
5. 音乐目录禁用（enabled=false）或文件已缺失：对应曲目会对客户端隐藏（`isAvailable=false`）。

## 6. 中文/日文搜索或分组不对

- 中文按**拼音首字母**分组（如"周杰伦"→ Z），个别多音字可能不准（可增强项，暂无人工纠错表）。
- 日文/韩文/数字/符号归入 `#` 组。
- 若刚扫描完分组未刷新，重新触发扫描（分组在扫描时计算并持久化）。

## 7. 播放失败 / 无声 / 格式不支持

- Bifrost `stream` **直出原文件、不转码**（无 ffmpeg 转码链路），客户端必须支持你的音频编码（MP3/FLAC/M4A 通常都没问题；无损 FLAC 在部分低端客户端/浏览器上可能不支持）。
- 播放中断可尝试：换有线网络 / 降低客户端缓冲；Range/206 已支持，拖动进度条正常。
- 专辑/歌单整体下载（zip）为可增强项，`download` 目前支持单曲。

## 8. 反向代理 / HTTPS / 容器相关

- **反向代理**：Subsonic 请求是普通 HTTP GET，任何反代均可；把 `/rest` 与 `/api` 都代理到 18080，地址则填反代域名。注意启用 HTTPS 后再暴露公网（明文密码传输风险）。
- **路径前缀**：Bifrost 无内置 context-path，若反代加了前缀（如 `https://域名/bifrost`），客户端地址相应填 `https://域名/bifrost/rest`。
- **Docker**：M1 暂未提供镜像（规划见《整体技术架构》§9.1）；自建容器时挂载 `./data` 卷并映射 18080 端口。

## 9. 数据备份与迁移

- 备份 = 复制整个 `./data`（SQLite 库 + 封面缓存 + 密钥），见 [01](01-安装与启动.md) §7。
- 迁移到新机器：装好 Java 21 → 拷入 `./data` → 启动（无需再设初始密码，账号在库里）→ 确认各音乐目录/图书目录的路径在新机器上仍有效，必要时改路径并重新扫描。

## 10. 电子书 / OPDS 连不上（阅读器专用）

> 阅读器连接操作见 [04-连接阅读器客户端](04-连接阅读器客户端.md)（OPDS 地址唯一正确填法是 `http://主机:18080/opds/v1.2/catalog`）。

| 现象 | 原因与处理 |
| --- | --- |
| 填 `http://主机:18080/opds`（或 `/opds/`、`/opds/v1.2`、多了尾斜杠）→ **404** | Bifrost 的 OPDS 挂在 `/opds/v1.2/` 路径下，**没有** `/opds` 快捷入口、不做自动跳转。填完整路径 `http://主机:18080/opds/v1.2/catalog`（见 [04](04-连接阅读器客户端.md) §3.1） |
| Readest 添加后一直失败/转圈 | **用的是 readest.com 网页托管版**：其同源代理带 SSRF 防护，生产环境会拦 `localhost`/局域网地址。改用 **Readest 桌面端**（原生直连，无 CORS 限制） |
| 目录能打开，但"全部图书/最近添加"是空的 | ① 没建图书目录 / 没扫描：`curl -u admin:密码 http://localhost:18080/api/book-roots` 看列表，没有就先建目录+扫描（[04](04-连接阅读器客户端.md) §1）；② 书目录里没有 EPUB（含 kepub.epub）/PDF（TXT/MOBI 不支持）；③ 扫描还在进行中（`GET /api/book-roots/scan/status` 未到 IDLE） |
| 目录有书，但某本打不开/下载失败 | ① 只支持 EPUB / PDF，其它格式不会出现在目录里；② 文件损坏或已被移动删除时该书 `isAvailable=false`，对客户端隐藏或下载 404；③ 关闭了 require-auth 却填了账号（或反之），见 [04](04-连接阅读器客户端.md) §3.3 |
| 手机/墨水屏连不上（Readest/KOReader） | 地址用了 `localhost`（指设备自己）→ 填 Bifrost 主机局域网 IP；并放行防火墙 18080 端口（见 §2） |
| 开启 require-auth 后返回 401 | OPDS 用 HTTP Basic，用户名/密码 = 管理员账号（默认 `admin`）；改过密码用新密码重连（见 [04](04-连接阅读器客户端.md) §3.3） |
| KOReader 里看不到"搜索" | OPDS 搜索入口在目录根已声明（OpenSearch），进入"全部图书/最近添加"后在页面内找搜索按钮；个别版本需先进入某个子目录才显示 |
