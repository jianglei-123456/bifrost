## 1. 排查顺序（先看这条）

遇到任何"连不上"问题，按顺序自查：

1. **服务在跑吗**（Bifrost 机器上）：`curl http://localhost:8080/api/ping` → `pong`？
2. **端口通吗**（客户端设备上）：浏览器打开 `http://192.168.1.10:8080/api/ping` 有结果？
3. **认证对吗**：`curl "http://localhost:8080/rest/ping.view?u=admin&p=你的密码&v=1.16.1&c=test"` → `status="ok"`？
4. **客户端字段对吗**：对照 [02](02-连接Subsonic客户端.md) §4 的填写清单。

第 1、2 步不过 → 看 §2；第 3 步不过 → 看 §3；只有第 4 步不过 → 看 [02](02-连接Subsonic客户端.md) §2/§4。

## 2. 连不上 / 超时 / 拒绝连接

| 现象 | 原因与处理 |
| --- | --- |
| 本机能访问，手机/其它设备不行 | 地址用了 `localhost`（指设备自己）；改填 Bifrost 主机局域网 IP（[02](02-连接Subsonic客户端.md) §2.1） |
| 局域网内也无法访问 | ① 防火墙未放行 8080 端口；② Bifrost 只监听了回环地址——确认应用配置的是 `0.0.0.0` 或未限制绑定地址；③ 路由器 AP 隔离（访客网络） |
| 端口不通但应用在跑 | `server.port` 被改过；或 Docker/反向代理映射了别的端口（见 §8） |
| 能打开但一直转圈 | 地址填到了具体端点（如 `/rest/ping.view`）导致 404；只填到主机:端口（[02](02-连接Subsonic客户端.md) §2.2） |

## 3. 认证失败（error 40）

Subsonic 认证失败统一返回 `status="failed"` + `error code="40"`（协议特性，非 HTTP 401）。

| 原因 | 处理 |
| --- | --- |
| 用户名/密码拼写错误 | 用户名默认 `admin`；密码为初始密码（[01](01-安装与启动.md) §3） |
| **首次启动没设初始密码** | 未注入 `BIFROST_AUTH_INITIAL_PASSWORD` 时密码不会写入数据库，任何密码都失败。兜底见下方"密码忘记" |
| 改过密码后客户端仍用旧密码 | 所有客户端用新密码重连（[01](01-安装与启动.md) §6） |
| 密码含特殊字符被 URL 转义破坏 | 客户端应自行 URL 编码；排查时用 curl 的 `--data-urlencode` |

**密码忘记（含首次未设置）兜底**：v1 无找回机制。若数据目录可牺牲，删除数据目录（默认 `./data`）后重新启动并设置初始密码——**注意：媒体索引、歌单、收藏、评分全部重置**，需重新扫描（音乐文件本身不受影响）。操作前先备份（[01](01-安装与启动.md) §7）。

## 4. 客户端报"未实现 / error 0"

Bifrost 按《音乐管理功能说明》§8.2 能力矩阵实现端点，未实现端点返回 `error code="0"`（如 getLyrics、Sharing/Podcast、Jukebox、转码相关）。**这不是配置错误**。列表中的"⏳ 可增强"项在后续版本逐步补齐。常见受影响功能：歌词显示、播客、点唱机、部分"相似歌曲/艺术家信息"（依赖 last.fm，未接入）。

## 5. 能连上但看不到音乐 / 列表为空

1. 库根是否配置且启用：`curl -u admin:密码 http://localhost:8080/api/library-roots`（[01](01-安装与启动.md) §5.2）。
2. 是否扫描过：触发 `POST /api/scan` 后查看 `GET /api/scan/status` 统计；新加文件需重新扫描（增量，很快）。
3. 文件格式：仅 MP3 / FLAC / M4A 参与索引聚合；WAV 可播不入聚合；WMA/APE 不支持。
4. 库根禁用（enabled=false）或文件已缺失：对应曲目会对客户端隐藏（`isAvailable=false`）。

## 6. 中文/日文搜索或分组不对

- 中文按**拼音首字母**分组（如"周杰伦"→ Z），个别多音字可能不准（可增强项，暂无人工纠错表）。
- 日文/韩文/数字/符号归入 `#` 组。
- 若刚扫描完分组未刷新，重新触发扫描（分组在扫描时计算并持久化）。

## 7. 播放失败 / 无声 / 格式不支持

- Bifrost `stream` **直出原文件、不转码**（无 ffmpeg 转码链路），客户端必须支持你的音频编码（MP3/FLAC/M4A 通常都没问题；无损 FLAC 在部分低端客户端/浏览器上可能不支持）。
- 播放中断可尝试：换有线网络 / 降低客户端缓冲；Range/206 已支持，拖动进度条正常。
- 专辑/歌单整体下载（zip）为可增强项，`download` 目前支持单曲。

## 8. 反向代理 / HTTPS / 容器相关

- **反向代理**：Subsonic 请求是普通 HTTP GET，任何反代均可；把 `/rest` 与 `/api` 都代理到 8080，地址则填反代域名。注意启用 HTTPS 后再暴露公网（明文密码传输风险）。
- **路径前缀**：Bifrost 无内置 context-path，若反代加了前缀（如 `https://域名/bifrost`），客户端地址相应填 `https://域名/bifrost/rest`。
- **Docker**：M1 暂未提供镜像（规划见《整体技术架构》§9.1）；自建容器时挂载 `./data` 卷并映射 8080 端口。

## 9. 数据备份与迁移

- 备份 = 复制整个 `./data`（SQLite 库 + 封面缓存 + 密钥），见 [01](01-安装与启动.md) §7。
- 迁移到新机器：装好 Java 21 → 拷入 `./data` → 启动（无需再设初始密码，账号在库里）→ 确认库根路径在新机器上仍有效，必要时改路径并重新扫描。
