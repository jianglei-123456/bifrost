> 本章是阅读器连接 Bifrost 书库的**唯一权威入口**：回答"OPDS 地址 / 用户名 / 密码到底怎么填"。Bifrost 自带 **OPDS 1.2** 服务端（与音乐侧 Subsonic 相互独立），**Readest**（桌面）与 **KOReader**（手机/墨水屏）等阅读器可直接浏览、搜索、下载 EPUB / PDF。

---

## 1. 前置条件：先建图书目录并扫描（首次使用必做）

图书与音乐是**两套独立目录**：音乐用 `/api/music-roots`，图书用 `/api/book-roots`（`mediaType=BOOK`）。OPDS 里能看到什么书，取决于图书目录扫描入库了什么，所以首次使用前必须先建目录 + 扫描：

- 支持的格式：**EPUB**（含 `.kepub.epub`）/ **PDF**；扫描按文件解析元数据（书名、作者、封面等），不支持 TXT/MOBI 等格式。
- 以下命令在 Bifrost 所在机器执行，`/api/**` 需要管理员账号（HTTP Basic，默认 `admin`）：

```bash
# ① 新建图书目录（path 指向含 EPUB/PDF 的目录，Windows 路径在 JSON 里反斜杠要写成 \\）
curl -u admin:你的密码 -H "Content-Type: application/json" \
  -d '{"name":"我的书库","path":"D:\\Books"}' \
  http://localhost:18080/api/book-roots

# ② 查看图书目录列表，记下返回的 {id}
curl -u admin:你的密码 http://localhost:18080/api/book-roots

# ③ 触发该图书目录扫描（异步，立即返回 SCANNING）
curl -u admin:你的密码 -X POST http://localhost:18080/api/book-roots/{id}/scan

# ④ 轮询扫描状态，直到 scanStatus 变为 IDLE 才代表扫完
curl -u admin:你的密码 http://localhost:18080/api/book-roots/scan/status
```

- 新增/删除书文件后，重新执行 ③ 即可增量扫描（重复触发安全）；改文件后需 `?force=true` 全量重读。
- 扫描完成后用 §5 的命令验证 OPDS 里已有图书，再去连客户端。

## 2. 连接要素

OPDS 目录**默认匿名可访问**，连接要素最多只有两个：

| 要素 | 填什么 | 说明 |
| --- | --- | --- |
| **地址（URL）** | 目录根 URL，规则见 §3 | 唯一正确写法见 §3.1 |
| **用户名 / 密码** | 留空 | 默认匿名；仅当开启 `bifrost.opds.require-auth: true` 时才必填，且与管理员账号一致（默认 `admin` + 你的密码） |

## 3. 服务器地址怎么填（重点）

### 3.1 唯一正确填法

> **OPDS 目录根要填完整路径：**
>
> ```
> http://<主机>:18080/opds/v1.2/catalog
> ```
>
> 而不是 `http://<主机>:18080/opds`。

Bifrost 的 OPDS 挂在 **`/opds/v1.2/`** 路径下（OPDS 1.2 标准路径），**没有** `/opds` 快捷入口，也**不做**尾斜杠/缺路径的自动跳转。填错路径会直接 404。实测对照：

| 填法 | 结果 |
| --- | --- |
| `http://localhost:18080/opds` | ❌ 404 |
| `http://localhost:18080/opds/` | ❌ 404 |
| `http://localhost:18080/opds/v1.2` | ❌ 404 |
| `http://localhost:18080/opds/v1.2/catalog/`（多了尾斜杠） | ❌ 404 |
| **`http://localhost:18080/opds/v1.2/catalog`** | ✅ 200（OPDS 目录根） |

目录根是一个 **navigation feed**（标题"Bifrost 图书库"），含两个子目录：**全部图书** 与 **最近添加**；阅读器内点进即可浏览。也可以直接订阅二级 feed：

| 用途 | 地址 |
| --- | --- |
| 目录根（默认填这个） | `http://主机:18080/opds/v1.2/catalog` |
| 全部图书（分页，每页 50） | `http://主机:18080/opds/v1.2/catalog/all?page=1` |
| 最近添加 | `http://主机:18080/opds/v1.2/catalog/recent` |
| 搜索 | 无需手填——feed 已声明 OpenSearch，客户端内输入关键字即可 |

### 3.2 主机写什么（端口与跨设备）

| 场景 | 地址 |
| --- | --- |
| 阅读器与 Bifrost 在同一台机器 | `http://localhost:18080/opds/v1.2/catalog` |
| 局域网内其它设备（手机/墨水屏/另一台电脑） | `http://<Bifrost主机的局域网IP>:18080/opds/v1.2/catalog`，如 `http://192.168.1.10:18080/opds/v1.2/catalog`（查 IP：Windows `ipconfig`，Linux `ip addr`） |
| 经反向代理公网/HTTPS 访问 | `https://你的域名/opds/v1.2/catalog`（默认 443 端口可省略） |

- **端口**：本仓库 `application.yml` 的 `server.port` 为 `18080`；若你改过端口，所有地址里的 `18080` 一并换成实际端口。
- **跨设备连不上**：手机/墨水屏上填 `localhost` 指的是设备自己——要填电脑的局域网 IP，并放行防火墙对应端口（[03](03-常见问题.md) §2）。

### 3.3 用户名与密码（可选鉴权）

- 默认匿名，用户名/密码留空即可。
- 若在 `application.yml` 设置了 `bifrost.opds.require-auth: true`，则所有 OPDS 请求要求 HTTP Basic，账号 = 管理员账号（默认 `admin`），密码 = 该账号密码（见 [01-安装与启动](01-安装与启动.md) §3/§6）。改密码后阅读器需用新密码重连。

## 4. 客户端填写步骤

### 4.1 Readest（桌面版，推荐首选验证）

1. 顶部 **Import（导入）菜单 → Online Library（在线书库）**。
2. 地址填 §3.1 的目录根 URL，如 `http://localhost:18080/opds/v1.2/catalog`；用户名/密码按 §3.3（默认留空）。
3. 打开后书架顶栏出现目录，进入 **全部图书 / 最近添加** 浏览；封面、下载、阅读（EPUB 在线阅读 / 整本下载）均可用。
4. 在某个 feed（含深层子目录）内选 **Add to My Catalogs** 可收藏该 feed，之后不必重填地址。
5. 搜索：书架顶栏搜索框输入关键字（走 OPDS OpenSearch）。

> ⚠️ **用 Readest 桌面端（Tauri），不要用 readest.com 的网页托管版连本机/内网**：网页托管版的同源代理带 SSRF 防护，生产环境会拦截 `localhost` / 局域网地址（详见 [03-常见问题](03-常见问题.md) §10）。

### 4.2 KOReader（Android / 墨水屏）

1. 顶栏 **Search（搜索）图标 → OPDS catalog**，进入 OPDS 目录浏览器（不同版本入口措辞略有差异）。
2. 在其 **目录管理（Catalog management / +）** 中新增目录：地址填 §3.1 的目录根 URL（局域网场景用电脑 IP），需要时可填用户名/密码。
3. 打开目录 → **全部图书 / 最近添加** 浏览；图书条目可直接打开阅读或下载（EPUB 走 EPUBC 直读，PDF 整本下载）。

## 5. 连接验证（不依赖客户端）

先用 curl 确认 OPDS 通了再排查客户端，能快速定位问题在哪一层（在 Bifrost 所在机器执行）：

```bash
# 目录根 → 200 且返回 Atom feed（标题 "Bifrost 图书库"）
curl http://localhost:18080/opds/v1.2/catalog

# 全部图书 feed → 200（里面 <entry> 即书库中的书；无 <entry> 说明还没书，回到 §1）
curl http://localhost:18080/opds/v1.2/catalog/all

# 开启 require-auth 后需带账号：
curl -u admin:你的密码 http://localhost:18080/opds/v1.2/catalog
```

- 目录根返回 200 + Atom：服务、地址正确；问题在客户端填写细节（对照 §3/§4）。
- 返回 **404**：地址填错（最常见是少了 `/v1.2/catalog`），对照 §3.1。
- 返回 200 但无图书条目：图书目录没建/没扫描，或目录里没有 EPUB/PDF，回到 §1。
- 返回 401（仅开启 require-auth 后）：缺用户名/密码或账号不对，对照 §3.3。

> Windows 下 curl 自带；也可直接在浏览器打开目录根 URL，看到 XML 即通。

## 6. 连上之后能做什么

| 能力 | 说明 |
| --- | --- |
| 浏览 | 目录根两个子目录：全部图书（分页）/ 最近添加 |
| 搜索 | 按书名/作者/系列/出版社/主题等关键字（OpenSearch） |
| 下载 | 整本下载 EPUB / PDF（文件端点支持 HTTP Range/206） |
| 封面 | 目录内展示图书封面（动态抽取端点，Readest / KOReader 均兼容） |
| 阅读 | KOReader：EPUB 直读（EPUBC）+ 下载；Readest：EPUB 在线阅读 + 整本下载 |

未实现能力：OPDS-PSE 按页流式、OPDS 2.0 JSON feed、WebDAV 整目录传输——客户端相应入口不可用属正常，不影响上述浏览/下载能力。

## 7. 阅读进度同步（KOSync，M3-sync）

浏览/下载之外，Bifrost 还提供**阅读进度同步**：设备上读到哪，换一台设备接着读。

**第 1 步：拿同步账号**（管理端 →「阅读进度」页）

页面上有**服务器地址**、**用户名**、**口令**（口令默认打码，点"显示"看明文；也可以点"生成口令"换一个随机口令）。同步账号与管理员账号是**两套凭据**——后端会拒绝把同步口令设成与管理员口令相同。

**第 2 步：配置设备**（KOReader）

1. *Tools → Progress sync → Custom sync server* → 填 `http://<Bifrost 主机>:18080`
   ⚠️ 输入框预填的是 `https://`，**必须手动改成 `http://`**（协议不会自动补 scheme）。
2. 返回 *Progress sync* → **Register / Login** → 填同步账号的用户名与口令 → 出现 "Registered to KOReader server." / "Logged in to KOReader server." 即成功（两个按钮都可用）。
3. 打开 **"Automatically keep documents in sync"**。
4. **Document matching method 保持 "Binary"**——改成 "Filename" 会让已同步的进度全部匹配不上（协议只认文件指纹）。

**第 3 步：多设备** — 每台设备重复第 2 步，**共用同一个同步账号**；打开同一本书时会提示是否跳到其他设备的位置。

**第 4 步：在管理端看结果** —「阅读进度」页显示每本书的百分比、来自哪台设备、最后上报时间；可以"重置进度"（只删服务端记录，设备本地位置不变）。匹配不到图书的记录进入**「孤儿进度」**页签（侧载文件、重打包的书等），可人工绑定、重新匹配或忽略。

**常见现象（不是故障）**：`auto_sync` 默认是关的（必须打开）；翻页推送有 10 秒防抖、全局 25 秒去抖，**手动"Push progress from this device now"最可靠**；书只在关书/挂起时自动推送；设备离线期间的推送可能丢失（客户端队列"发一次就丢"），下次打开书会重新拉取比对。
