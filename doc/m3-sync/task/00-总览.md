# M3-sync 里程碑任务总览（阅读进度同步 / KOSync）

| 项 | 内容 |
| --- | --- |
| 里程碑 | M3-sync（**仅图书侧阅读进度同步**） |
| 本轮范围 | 同步账号 + 文档指纹映射 + KOSync 4 端点（+ `/healthcheck`）+ 管理 REST `/api/book-sync/**` + 自动扫描 + 孤儿进度；**不含**书签/高亮/笔记同步、阅读统计、WebDAV、OPDS-PSE、多用户 |
| 依据 | `doc/adr/0006-kosync-self-implemented.md`、`doc/m3-sync/调研/01-KOSync协议实证.md`、`CONTEXT.md`（增补后） |
| 交付形态 | 分 5 个任务阶段推进，每阶段可编译、可测试、可提交 |
| 状态 | **completed**（Day-one，2026-09-10） |

## 1. 验收标准

1. KOReader 设备把 Custom sync server 指向 `http://<host>:18080` 后，**Register/Login 成功、推送/拉取进度成功、两台设备能互相续读**（真机验证由用户执行，见 §7 自测清单）；
2. KOSync 5 个端点的状态码/响应体**逐条满足**调研档 §3 的 15 条客户端硬约束（hurl 契约测试覆盖）；
3. 阅读进度与图书建立**指纹→书映射**：管理端可按书展示进度、可发现孤儿进度、可重置某本书进度；
4. 未匹配的新指纹触发**一次**图书扫描（无冷却；同一指纹只触发一次；扫描中则跳过）；
5. 同步账号独立于管理员账号，且**强制两者口令不同**；管理端可配置并回显同步口令；
6. 文档齐备：ADR-0006 + 调研档 + 本任务档 + hurl 契约 + 构建全绿 + 旧文档回填（§8）。

**不设为验收门槛**：真机测试（用户自测）、Readest（只要求"不被我们破坏"）。

## 2. 阶段与依赖

```
01 同步核心 ──► 02 KOSync 端点 ──► 04 测试与收尾
       │                │
       └──► 03 管理 REST ┴──► 06 前端对接（契约）
05 延后项（本轮不做清单）
```

- 01 → 02：实体、`document` 指纹、书匹配、自动扫描是端点层的共同依赖；
- 01 → 03：管理 REST 读的是同一批实体；
- 02/03 → 04：hurl 契约 + 集成测试；
- 每阶段完成标准：`./mvnw -pl <模块> -am compile` 通过 + 该阶段测试通过 + 提交。

## 4. 技术栈与依赖增量

| 依赖 | 版本 | 说明 |
|---|---|---|
| 现有全部依赖 | — | **零新增第三方依赖**：KOSync 端点用 Spring MVC + Jackson，指纹用 JDK `MessageDigest` |

**不引入**：OpenResty/Redis/Lua 栈、任何 KOSync 服务端复刻库、Atom/XML 之外的模板引擎。

## 5. 与 M2-book（现有图书侧）的边界

| 共享 | 隔开 |
|---|---|
| `bifrost-domain`（新增 3 个实体，不动既有实体除 `Book` 加一列）、`BifrostProperties` | `kosync` 协议栈与 `/opds/**` 完全独立的路由/异常处理/安全链 |
| `BookScanService`（**唯一改动点**：解析后补算文档指纹 + 增量跳过时自愈） | 管理端点：`/api/book-sync/**` vs `/api/books`、`/api/book-roots` |
| `Book`（新增 `partial_md5` 列，可空） | 进度/账号/设备三张新表，**不**与 `book` 表级联外键（Book 删除后进度转孤儿） |
| `BookScanCompletedEvent`（自动扫描/孤儿回填的钩子） | 新增第 4 条 `SecurityFilterChain`（`/api/**`、`/rest/**`、`/opds/**` 之外的 `/users/**`、`/syncs/**`、`/healthcheck`） |
