## T4.2 集成测试（`bifrost-bootstrap/src/test/java/com/bifrost/bootstrap/`）

全部 `@SpringBootTest` + `@AutoConfigureMockMvc`，各自独立 `bifrost.db.path=target/test-data/*.db`（沿用既有约定）。

- `KosyncProtocolIntegrationTest` —— **完整设备握手**：
  `POST /users/create`（201）→ `GET /users/auth`（200）→ `PUT /syncs/progress`（200，含秒级 `timestamp`）→ `GET /syncs/progress/{doc}`（200，字段齐全）→ 换设备名再 PUT → GET 到最新值（**后写覆盖**）。
- `KosyncHardConstraintsTest` —— 逐条钉死客户端硬约束（每条一个 `@Test`，失败信息写明"客户端会怎样坏"）：
  1. `Content-Type` 以 `application/json` 开头（**不是** `application/vnd.koreader.v1+json`）；
  2. 未知 document → **200 且 body 为 `{}`**（不是 404）；
  3. 认证失败 → **401**（不是 403/404）；
  4. PUT 成功只有 **200**，任何分支都**不返回 202**；
  5. 注册成功只有 **201**；注册失败为 **402** 且 body 带非空 `message`；
  6. `progress` 原样回显（含换行/Unicode/长 XPointer 的往返一致）；
  7. `device` / `device_id` 原样回显（含中文与 emoji，**不做任何规范化**）；
  8. `percentage` 是 JSON 数字（`isNumber()` 断言），不是字符串；
  9. 无 3xx（断言状态码集合）；
  10. 未 gzip（断言无 `Content-Encoding`）；
  11. 协议 `timestamp` 为**秒级（`timestamp` 与 `Instant.now().getEpochSecond()` 相差 < 5）。
- `KosyncSecurityIntegrationTest` —— 无凭据 401；`/healthcheck` 匿名 200；**`bifrost.kosync.enabled=false` 时 5 个端点 404**（防裸奔回归）。
- `BookSyncAdminIntegrationTest` —— 账号读写（明文回显、口令强制不同）、进度列表分页/过滤、删除进度、孤儿绑定/忽略/rematch、设备列表、删书后进度转孤儿（`scanAttemptedAt != null`）。
- `UnmatchedProgressAutoScanIntegrationTest` —— 首推未知指纹触发**一次**扫描（用切面/计数器断言只触发一次）；库里有对应书时扫描结算后**自动绑定**（`matchSource=AUTO`）；库里没有则结算为**固定孤儿**，再推同一指纹**不再触发**扫描。

## T4.3 hurl 契约（`hurl/kosync/`）

现状：`hurl/run.ps1` 启动干净 jar → `setup.hurl` → `opds/` → `api/` + `rest/`。新增 `kosync/`，**排在 `opds/` 之后、`api/` 之前**（依赖已建好的图书库与扫描结果）。

`hurl/kosync/setup.hurl`：

1. `PUT /api/book-sync/account` 设置同步账号 `reader` / `synctest`（**必须与 admin 的 `testpass` 不同**，R2c）；
2. 建图书目录 + 扫描 + 轮询 `/api/book-roots/scan/status` 到 `IDLE`（沿用 `opds/setup.hurl:43-64` 的写法）；
3. 用 jsonpath 从 `GET /api/books?title=Test%20Book` **捕获 `partialMd5`**（为此 `BookDto` 增加 `partialMd5` 字段，见 03）→ 存为变量 `document`。

> 不把指纹硬编码进 hurl：从 API 捕获 + 单元测试的黄金值双重保护，算法回归时先红的是单测。

`hurl/kosync/protocol.hurl`：五个端点的契约矩阵（`x-auth-key: <md5("synctest")>` 为固定值，hurl 不提供 md5 函数，按 `hurl/README.md` 里 Subsonic 令牌的既有做法钉死 hex）；断言状态码、`Content-Type` 前缀、未知 document 的 `{}`、`timestamp` 存在、401 的 `message` 非空。

`hurl/kosync/orphan.hurl`：推送一个随机 32 位 hex → 断言出现在 `/api/book-sync/orphans` → 绑定到 `sample.pdf` 对应的书 → 断言进入进度列表；再推一个 → 忽略 → 断言默认列表不含它。

`hurl/run.ps1` 增加 `kosync/` 一段（与 `opds/` 同样 fail-fast）。

## T4.4 《KOReader 真机自测清单》（交付给用户）

> 前提：Bifrost 已启动（默认 `http://<host>:18080`），图书目录已扫描、书已入库。

1. **取同步账号**：管理端 →「阅读进度」→ 记下 `serverUrl`、用户名、口令（页面可回显明文）。
2. **设备 A 配置**：KOReader → *Tools → Progress sync → Custom sync server* → 输入 `http://<host>:18080`
   ⚠️ 输入框预填的是 `https://`，**必须手动改成 `http://`**；协议不会自动补 scheme。
3. 返回 *Progress sync* → **Register / Login** → 填同步账号（首次点 Register 或 Login 都可以，两者等价）→ 出现 "Registered to KOReader server." / "Logged in to KOReader server."。
4. 打开 **"Automatically keep documents in sync"**；**Document matching method 保持 "Binary"**（改成 Filename 会让所有进度变孤儿）。
5. **正例**：用 Bifrost 的 OPDS 目录下载一本书（保证文件与库里一致）→ 打开、翻几页 → *Progress sync → Push progress from this device now*。
   - 管理端「阅读进度」应出现一行：书名、百分比、设备名、时间正确。
   - 客户端有 25 秒全局去抖，**手动推送最可靠**（自动推送要等翻页/挂起/关书触发）。
6. **多端续读**：设备 B 用**同一个同步账号** → 打开同一本书（同样从 OPDS 下载）→ *Pull progress from other devices now* → 应跳到设备 A 的位置。
7. **负例（孤儿）**：设备打开一本**侧载**（不经 OPDS）的书 → 推送 → 管理端应出现一条**孤儿进度**，页面上能看到"已尝试匹配"标记；用「重新匹配 / 绑定 / 忽略」三个动作各试一次。
8. **负例（认证）**：管理端改同步口令 → 设备再推送应报**认证失败**（不是"网络错误"）→ 在设备上重新 Login 后恢复。
9. **对账**：`data/logs/bifrost.log` 里能按 `kosync` 关键字找到 401 与自动扫描/结算日志。

**已知的客户端行为（不是 Bug，不要报障）**：`auto_sync` 默认关；翻页推送有 10s 防抖、全局 25s 去抖；关书时才推送；离线队列"发一次就丢"（服务端不可用期间的推送会丢，重连后会补发队列里剩下的）；设了自定义设备名的设备会对自己的进度弹"是否同步"（客户端自身的不对称比较，服务端无法修）。
