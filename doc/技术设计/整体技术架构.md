## 1. 项目概述

家庭媒体库管理平台，统一管理三类媒体资源：

| 媒体类型 | 核心能力 | 所在包 | 状态 |
| --- | --- | --- | --- |
| 音频 audio（音乐） | 扫描、标签解析、聚合索引、Subsonic 服务 | `com.bifrost.core.audio` | ✅ 本轮交付 |
| 视频 video | 媒体扫描、索引 | `com.bifrost.core.video` | 后续 |
| 电子书 book | 元数据解析 | `com.bifrost.core.book` | 后续 |

对外能力：**Bifrost 自身提供 Subsonic 兼容协议服务（Syrinx，`/rest/**`）**，客户端直连；图书侧提供 OPDS 1.2（`/opds/**`）、阅读进度同步提供 KOSync（`/users`、`/syncs`、`/healthcheck`）；管理端（Vue Dashboard）是独立仓库 `../bifrost-dashboard`，**1.0.0 起与后端打进同一镜像、挂在 `/admin/`**（ADR-0007）；Jellyfin 推送为后续预留。

## 3. 模块架构

```
bifrost (父级 POM，统一版本)
├── bifrost-common        # 工具包：字符串、日期、文件 IO、自定义异常（纯 Java，无 Spring）
├── bifrost-domain        # 实体（Entity）、DTO、枚举、Repository 接口
├── bifrost-core          # 核心业务（Service 层），包隔离 video / audio / book
├── bifrost-adapter       # 对接外部客户端（聚合 POM）
│   ├── syrinx            # 【音乐网关】聚合模块
│   │   └── subsonic-api  # Subsonic 协议服务端（/rest/**，MVC Controller）
│   ├── opds-publisher    # 图书 OPDS 1.2 流发布（/opds/**，M2-book）
│   ├── kosync-server     # 阅读进度同步 KOSync（/users、/syncs、/healthcheck，M3-sync）
│   └── jellyfin-client   # 占位（视频配套，待定）
├── bifrost-api           # 管理 RESTful Controller 层（/api/**，供管理端调用）
└── bifrost-bootstrap     # 启动类 + application.yml + 管理端静态托管，生成可执行 jar
```

> 变更说明：原 `sonic-client`（向外部 Sonic 推送）**移除**——产品方向反转，Bifrost 自身即 Subsonic 服务端，音乐网关改名 **syrinx** 并内含 `subsonic-api`。

**依赖关系（单向，禁止反向/循环）**：

```
bifrost-common ◄── bifrost-domain ◄── bifrost-core ◄── bifrost-adapter（聚合，子模块继承）
bifrost-core ◄── bifrost-api ◄── bifrost-bootstrap
bifrost-core ◄── bifrost-adapter/syrinx/subsonic-api ◄── bifrost-bootstrap
```

**包约定**：基础包 `com.bifrost.*`；core 内 `com.bifrost.core.{video,audio,book}` 包隔离；adapter 子模块 `com.bifrost.adapter.{syrinx,jellyfin,opds}`，其中 `com.bifrost.adapter.syrinx.subsonic` 承载 Subsonic 实现。

## 4. 分层与依赖规则

| 规则 | 说明 |
| --- | --- |
| 依赖单向 | common ← domain ← core ← adapter；core ← api ← bootstrap |
| common 无 Spring | 纯 Java 工具与异常，禁止 Spring 依赖 |
| core 无 Web/持久化 | 仅 `spring-boot-starter`；扫描/解析 Service 为普通 `@Service`；Repository 接口在 domain，JPA 实现在各模块运行时装配 |
| subsonic-api 位置 | 位于 adapter 层（用户决策），可引入 `spring-boot-starter-web`；控制器由 bootstrap 跨模块扫描注册（`scanBasePackages="com.bifrost"`） |
| 版本统一 | 内部模块父 POM dependencyManagement 声明 `${project.version}`，子模块不写版本号 |
| 打包 | 仅 bifrost-bootstrap 配置 spring-boot-maven-plugin 生成可执行 fat jar |

## 5. 存储设计

| 项 | 设计 |
| --- | --- |
| 数据库 | SQLite 单文件（默认 `${bifrost.data.dir}/bifrost.db`，可用 `bifrost.db.path` 单独覆盖） |
| ORM | Spring Data JPA（Hibernate）+ `hibernate-community-dialects` 的 SQLiteDialect |
| Schema | 当前版本用 `ddl-auto=update`；后续引入迁移工具（可增强） |
| SQLite 运行参数 | 启用 WAL、busy_timeout，避免读写互斥 |
| 事务 | 边界在 core Service（`@Transactional`）；扫描按文件批次提交 |
| 备份 | 停止写操作后复制数据目录（容器场景=复制宿主卷，如 `/srv/bifrost/data`） |
| 领域模型 | Artist / Album / Track / LibraryRoot / User / Playlist / PlaylistEntry（字段级设计见《音乐管理技术设计》第 1 章） |

## 6. 配置体系

```yaml
bifrost:
  data:
    dir: ./data                      # 数据目录根：db / 封面缓存 / 日志都由它派生（容器里 /data）
  db:
    path: ${bifrost.data.dir}/bifrost.db   # 可单独覆盖（测试与 hurl 就用它指向临时库）
  media:
    cover-cache-dir: ${bifrost.data.dir}/covers   # 封面缩略图缓存
  scan:
    cron: "0 0 3 * * *"              # 定时扫描 cron（6 段含秒；留空=关闭）
    batch-size: 200                  # 扫描批事务的文件数
  auth:
    initial-username: admin          # 初始管理员用户名
    # initial-password: 仅环境变量 BIFROST_AUTH_INITIAL_PASSWORD 注入
    # secret: 环境变量 BIFROST_AUTH_SECRET（口令加密主密钥；缺失自动生成落 <data.dir>/secret.key）
  subsonic:
    enabled: true
    api-version: 1.16.1              # 对外宣称的协议版本
  opds:
    require-auth: false              # true 时 /opds/** 走 HTTP Basic
  kosync:
    enabled: true                    # 关闭后 5 个端点必须 404
    registration-enabled: true       # 是否放行 POST /users/create 自助注册
    auto-scan-on-unmatched: true     # 未匹配的文档指纹触发一次图书扫描
    public-base-url: ""              # 展示给阅读设备的同步地址；空=按请求 Host 兜底
  cors:
    allowed-origins:                  # 跨域来源白名单；空列表=禁用 CORS，默认 *（所有来源）
      - "*"

spring:
  jpa:
    hibernate.ddl-auto: update
  servlet:
    multipart:
      max-file-size: 5MB             # 封面单文件上限（与 BookCoverController 校验一致）
      max-request-size: 6MB
  datasource:                        # 由自定义 DataSource 配置指向 SQLite 文件
    url: jdbc:sqlite:./data/bifrost.db
```

> 库根（音乐目录 / 图书目录）**不是配置项**：`bifrost.library.roots` 是预留未实现的键，
> 唯一写入通道是管理端 REST（`/api/music-roots`、`/api/book-roots`），落在 DB 的 `library_root` 表。
> 环境变量覆盖按宽松绑定写（`bifrost.scan.cron` → `BIFROST_SCAN_CRON`）。

覆盖机制：环境变量 / 启动参数 > `SPRING_CONFIG_ADDITIONAL_LOCATION` 外部 yml > 内置 application.yml（详见《通用功能说明》第 2 章）。

## 7. 认证实现要点

| 项 | 设计 |
| --- | --- |
| 账号 | 单管理员（User 表预留多用户） |
| 口令存储 | **AES-GCM 可逆加密**（主密钥：环境变量 `BIFROST_AUTH_SECRET`，缺失自动生成落 `data/secret.key` 并警告）——因 Subsonic 令牌 `md5(password+salt)` 验证必须还原明文（见《Subsonic_API_参考》2.2） |
| Subsonic 认证 | `t/s` 令牌（解密后计算 `md5(password+salt)`，恒定时间比较）或 `p` 密码；失败 `200 + status=failed + error 40` |
| 管理 REST 认证 | HTTP Basic 或同款 t/s 令牌；失败 `401 + 信封 code=1002` |
| 安全建议 | 对外走 HTTPS（反代）；`p=enc:` 仅编码非加密 |

## 8. Subsonic 服务技术要点（Syrinx）

| 项 | 设计 |
| --- | --- |
| 挂载 | `/rest/<method>.view`（`@RestController` 映射，`@RequestMapping("/rest")`） |
| 双格式 | XML 默认 + `f=json`（jackson-dataformat-xml；JAXB 不引入） |
| 信封 | `subsonic-response`：status/version/type/serverVersion/openSubsonic（详见 API 参考第 3 章） |
| 认证拦截 | 解析 `u/t/s/p/v/c/f`，校验后放行；`getOpenSubsonicExtensions` 免认证 |
| 流式传输 | `stream/download` 支持 **HTTP Range/206**（`InputStreamResource` + 手动 Range 解析或 `ResourceHttpRequestHandler`）；`Accept-Ranges: bytes`；`X-Content-Type-Options: nosniff` |
| 错误 | 协议错误码 0/10/20/30/40/41/42/43/44/50/60/70（**无 80–99**，见 API 参考 3.2） |
| ID | `ar-/al-/tr-/pl-` + 数字主键 |
| 模拟目录树 | `getMusicDirectory` 按 `/艺术家/专辑/01 - 标题.mp3` 虚拟目录返回（兼容 DSub 系） |
| 缓存失效 | 订阅 `MusicScanCompletedEvent` 刷新（缩略图、nowPlaying 等进程内缓存） |
| 能力通告 | 无 `X-OpenSubsonic` 请求头（该头为讹传，不支持）；用响应字段 + `getOpenSubsonicExtensions` 通告 |

## 9. 构建与运行

```bash
./mvnw clean verify                                  # 全量构建（含全部测试）
./mvnw -pl bifrost-bootstrap -am spring-boot:run     # 开发启动，端口 18080
java -jar bifrost-bootstrap/target/bifrost-bootstrap-1.0.0.jar   # 跑构建产物
```

验证：`curl http://localhost:18080/api/ping` → `pong`；`curl -u admin:<口令> http://localhost:18080/api/version` → `{"code":0,...,"version":"1.0.0"}`；管理端 `http://localhost:18080/admin/`。

### 9.1 交付形态：单镜像（1.0.0 起）

一个镜像 = 后端 fat jar（**内含管理端产物**）+ `eclipse-temurin:21-jre`；一个进程、一个端口 18080，同时提供管理端页面与 `/api/**`、`/rest/**`、`/opds/**`、KOSync 端点。决策与被否决方案见 [ADR-0007](../adr/0007-single-image-admin-under-admin.md)；**命令清单见[操作手册 05](../操作手册/05-Docker部署.md)**（镜像不在仓库里自动构建，按那份清单依次执行）。

| 项 | 形态 |
| --- | --- |
| 基底 | `eclipse-temurin:21-jre`（Ubuntu 基底）；额外装 curl（healthcheck）与 tzdata（TZ 生效） |
| 运行身份 | 非 root，固定 uid/gid 1000；媒体目录**只读**挂载 |
| 管理端 | dashboard 以 `vite build --base=/admin/` 构建 → 拷入 `src/main/resources/static/admin/`（gitignore）→ 打进 jar → `AdminWebConfig` 托管在 `/admin/`，`/` 与 `/admin` 302 过去 |
| 根命名空间 | `/api/**` `/rest/**` `/opds/**` `/users` `/syncs` `/healthcheck` 原样保留；未匹配路径一律 404（SPA 兜底只作用于 `/admin/**`） |
| 数据 | 单卷 `/data`（`BIFROST_DATA_DIR`）：db、封面缓存、日志、`secret.key` |
| 镜像 | `ghcr.io/jianglei-123456/bifrost:1.0.0`（+ `:latest`）；OCI label 带 `version` 与 `revision`(git sha) |

`docker/docker-compose.yml`（节选，完整文件在仓库里）：

```yaml
services:
  bifrost:
    image: ghcr.io/jianglei-123456/bifrost:1.0.0
    ports: ["18080:18080"]                     # 端口是契约：三类客户端都按 18080 写
    environment:
      BIFROST_AUTH_INITIAL_PASSWORD: ${BIFROST_AUTH_INITIAL_PASSWORD:?首次启动必填}
      BIFROST_DATA_DIR: /data                  # db / covers / logs / secret.key
      TZ: Asia/Shanghai                        # 定时扫描 cron 用 JVM 默认时区
      BIFROST_KOSYNC_PUBLIC_BASE_URL: ${BIFROST_KOSYNC_PUBLIC_BASE_URL:-}   # 展示给阅读设备的同步地址
    volumes:
      - /srv/bifrost/data:/data
      - /srv/bifrost/music:/media/music:ro     # 库根在管理端里按容器内路径添加
      - /srv/bifrost/books:/media/books:ro
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:18080/api/ping"]
```

- 数据备份：复制宿主 `/srv/bifrost/data` 即完成（含 db、封面缓存、`secret.key`——丢了它已加密的口令解不开）。
- 不带管理端产物的 jar（直接 `./mvnw package` 后 `java -jar`）：`/` 仍 302 到 `/admin/`，但那里没有 `index.html` 会 404——协议服务不受影响，这是预期行为（操作手册 05 §6）。
- Windows 宿主构建：管理端产物由 `../bifrost-dashboard` 构建后拷入 `src/main/resources/static/admin/`；compose 文件里的 `/srv/bifrost/*` 换成宿主实际路径。
