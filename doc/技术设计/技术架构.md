## 1. 项目概述

Bifrost 是一个**家庭媒体库管理平台**，统一管理三类媒体资源并对外提供服务：

| 媒体类型 | 核心能力 | 所在包 |
| --- | --- | --- |
| 视频 video | 媒体扫描、索引 | `com.bifrost.core.video` |
| 音频 audio | 标签解析 | `com.bifrost.core.audio` |
| 电子书 book | 元数据解析 | `com.bifrost.core.book` |

对外集成（关键层 `bifrost-adapter`）：

- **Jellyfin**：向 Jellyfin 推送 / 同步媒体信息
- **Sonic**：向 Sonic 服务推送媒体信息
- **OPDS**：生成图书 OPDS 流（Atom/XML），供阅读器订阅

对外接口：`bifrost-api` 提供 RESTful API，供 **Vue Dashboard** 前端调用。

## 3. 模块架构

### 3.1 目录与职责

```
bifrost (父级 POM，统一 Spring Boot 版本与依赖版本)
├── bifrost-common        # 工具包：字符串、日期、文件 IO、自定义异常（纯 Java，不依赖 Spring）
├── bifrost-domain        # 核心实体（Entity）、DTO、枚举、数据库 Repository 接口
├── bifrost-core          # 核心业务逻辑（Service 层），包隔离 video / audio / book
├── bifrost-adapter       # 【关键层】对接外部客户端（聚合 POM）
│   ├── jellyfin-client   # Jellyfin 推送/同步适配器
│   ├── sonic-client      # Sonic 推送适配器
│   └── opds-publisher    # 图书 OPDS 流生成适配器
├── bifrost-api           # RESTful Controller 层（供 Vue Dashboard 调用）
└── bifrost-bootstrap     # Spring Boot 启动类 + application.yml 配置
```

### 3.2 模块依赖关系（单向依赖，禁止反向/循环）

```
bifrost-common  ◄──  bifrost-domain  ◄──  bifrost-core  ◄──  bifrost-adapter (聚合)
                                                              ├── jellyfin-client
                                                              ├── sonic-client
                                                              └── opds-publisher
bifrost-core  ◄──  bifrost-api  ◄──  bifrost-bootstrap
```

- `bifrost-common`：无任何内部依赖，纯 Java 工具库
- `bifrost-domain`：依赖 common
- `bifrost-core`：依赖 common、domain，引入 `spring-boot-starter`（@Service 等容器能力）
- `bifrost-adapter`：聚合 POM（packaging=pom），统一声明对 `bifrost-core` 的依赖供三个子模块继承
- `bifrost-api`：依赖 core，引入 `spring-boot-starter-web`
- `bifrost-bootstrap`：依赖 api（传递获得 web），显式 `spring-boot-starter`，配置 `spring-boot-maven-plugin` 生成可执行 jar

### 3.3 包结构约定

- 全部模块基础包名：`com.bifrost.*`
- core 领域包隔离：`com.bifrost.core.video` / `.audio` / `.book`（避免领域逻辑相互耦合）
- adapter 子模块包：`com.bifrost.adapter.jellyfin` / `.sonic` / `.opds`

## 4. 关键技术设计

### 4.1 跨模块组件扫描

多模块工程下，启动类默认只扫描自身包，无法发现 `bifrost-api` 的 Controller 与 `bifrost-core` 的 Service：

```java
@SpringBootApplication(scanBasePackages = "com.bifrost")
public class BifrostApplication { ... }
```

统一扫描 `com.bifrost` 根包，保证各模块组件全部注册到容器。

### 4.2 版本统一策略

- 第三方依赖版本：由 `spring-boot-starter-parent` 的 dependencyManagement 统一管理（如 Lombok 版本经 `${lombok.version}` 属性注入 annotationProcessorPaths）
- 内部模块版本：父 POM dependencyManagement 声明 `com.bifrost:*` 为 `${project.version}`，子模块依赖不写版本号
- 编译目标：`<java.version>21</java.version>` → `<maven.compiler.release>21</maven.compiler.release>`

### 4.3 打包策略

- 仅 `bifrost-bootstrap` 配置 `spring-boot-maven-plugin`，`mvn package` 时 repackage 为可执行 fat jar（嵌套依赖置于 `BOOT-INF/`）
- 其余模块保持普通 jar，避免被错误地打成可执行包

### 4.4 依赖引入策略

- 骨架阶段遵循"仅基础"：common/domain 不引入 Spring Web 容器；core 仅引入 `spring-boot-starter`
- 持久层（JPA / MyBatis-Plus）、缓存（Redis）、监控（actuator）等**未引入**，待对应功能落地时按需添加（保持最小依赖）

### 4.5 健康检查占位接口

`bifrost-api` 提供 `GET /api/ping` → `pong`，用于验证 Web 链路与应用启动状态。

## 5. 构建与运行

```bash
# 全量构建（含测试）
./mvnw clean verify

# 启动应用（bootstrap 及其上游依赖模块一起构建）
./mvnw -pl bifrost-bootstrap -am spring-boot:run
```

- 默认端口：`8080`（application.yml 配置）
- 验证：`curl http://localhost:8080/api/ping` → `pong`
