## 3. 标签解析设计

### 3.1 实现位置

`bifrost-core` 的 `com.bifrost.core.audio` 包（遵循 core 无 web/持久化依赖约束）。

### 3.2 解析流程

```
AudioTagParser.parse(Path file) → TagResult
  ├─ 按扩展名分发（mp3→ID3、flac→Vorbis、m4a→MP4、wav→无标签）
  ├─ jaudiotagger AudioFileIO.read → Tag
  ├─ 抽取字段（映射表见《音乐管理功能说明》2.2）
  ├─ 规范化：trim；空值置 null；year 解析失败置 null
  └─ 封面：优先内嵌图（取首个）；无内嵌则目录 cover.jpg/folder.jpg
```

- 解析异常：捕获记录（错误计数），返回仅含文件名的兜底结果。
- **只读**：仅 `read`，绝不写回。

### 3.3 文件名兜底

无标题标签时：`文件名去扩展名` 作为标题；无艺术家时：**不参与艺术家聚合**（归"未知艺术家"展示分组）。

## 4. 扫描算法

### 4.1 流程（伪代码）

```
scan(root):
  if globalLock.isLocked(): return "扫描进行中"
  root.scanStatus = SCANNING
  files = walk(root.path)                        # 过滤支持扩展名
  dbTracks = trackRepo.findByLibraryRootId(root.id)
  dbIndex = indexByPath(dbTracks)                # path → Track
  for f in files:
    fp = fingerprint(f)                          # path+size+mtime
    t = dbIndex.remove(f.path)
    if t == null:                                # 新文件
      parseAndInsert(f, root)
      stats.added++
    elif t.fingerprint != fp:                    # 变更文件
      parseAndUpdate(t, f, fp)
      stats.updated++
    # 指纹一致 → 跳过
  for t in dbIndex.values():                     # 剩余 = 文件已消失
    t.isAvailable = false
    stats.missing++
  refreshAlbumAggregates()                       # 时长/曲目数/封面/艺术家专辑数
  publish MusicScanCompletedEvent(root, stats)
  root.scanStatus = IDLE; root.lastScanAt = now
```

### 4.2 关键点

| 项 | 设计 |
| --- | --- |
| 互斥 | 全局扫描锁（JVM 内 ReentrantLock + 状态位；多实例部署为可增强） |
| 幂等 | 指纹比对天然幂等，重复扫描无副作用 |
| 中断 | 进程被杀后状态标记残留 → 启动时重置 SCANNING→IDLE |
| 聚合刷新 | 仅对本次扫描涉及的专辑/艺术家增量刷新（避免全表） |

## 5. 拼音索引

- 库：**jpinyin**（`com.github.stuxuhai:jpinyin:1.1.8`），`PinyinHelper.getShortPinyin` 取首字母序列。
- 算法：

```
indexLetter(name):
  c = firstChar(name)
  if c 是 ASCII 字母 → uppercase(c)
  if c 是汉字 → 取拼音首字母（多音字由 jpinyin 短语词典消歧；失败则 '#'）
  else → '#'
```

- 持久化：Artist.indexLetter 在聚合时计算入库；查询直接按字段分组排序。
- 注意：jpinyin 对部分多音字（罕见字/人名）仍可能不准；可增强：人工纠错表。

## 6. Subsonic 端点实现设计（Syrinx）

### 6.1 模块结构

```
bifrost-adapter/syrinx/subsonic-api
├── com.bifrost.adapter.syrinx.subsonic
│   ├── SubsonicController        # @RestController("/rest")，端点映射
│   ├── auth/                     # 认证解析与校验（t/s、p）
│   ├── dto/                      # 响应模型（XML/JSON 双格式）
│   ├── service/                  # 端点→core Service 编排
│   ├── error/                    # 错误码枚举与响应组装
│   └── id/                       # ar-/al-/tr-/pl- ID 编解码
```

### 6.2 端点 → 领域映射（节选）

| Subsonic 端点 | 核心服务 | 说明 |
| --- | --- | --- |
| getIndexes / getArtists | ArtistService.indexes(folderId) | 按 indexLetter 分组 |
| getArtist | ArtistService.detail(id) | 含专辑列表（按年份） |
| getAlbum | AlbumService.detail(id) | 含曲目列表（discNo+trackNo） |
| getSong | TrackService.detail(id) | Child 结构 |
| getAlbumList(2) | AlbumService.list(type, size, offset) | type → 排序/过滤条件 |
| search3 / search2 | SearchService.search(query, counts) | 空查询返回全部（OS） |
| stream / download | StreamService.stream(id) | Range/206，见第 7 章 |
| getCoverArt | CoverService.cover(id, size) | 见第 8 章 |
| scrobble | TrackService.scrobble(id, time, submission) | 更新 playCount/lastPlayed + nowPlaying |
| getPlaylists / getPlaylist / createPlaylist / updatePlaylist / deletePlaylist | PlaylistService.* | 条目 position 维护 |
| getScanStatus / startScan | SubsonicAssembler.buildScanStatus() / MusicScanService.scanAll() | 均只针对音乐目录；startScan 后台异步执行并立即返回状态 |
| getUser / getUsers | UserService.* | 单用户语义 |

### 6.3 响应组装与双格式

- DTO 定义与 XML 属性一一对应（@JacksonXmlRootElement / @JacksonXmlProperty）。
- `f=json` → 同一 DTO 由 Jackson JSON 输出；XML 由 `jackson-dataformat-xml` 输出。
- 信封：`subsonic-response`（status/version/type=Bifrost/serverVersion/openSubsonic=true）。
- 二进制端点错误：Content-Type 以 `text/xml` 开头返回 error XML。

### 6.4 错误码映射

| 场景 | 错误码 |
| --- | --- |
| 认证失败 | 40 |
| 缺参 | 10 |
| 客户端版本过高/过低 | 30 / 20 |
| 数据不存在 | 70 |
| 权限（单用户下管理端点） | 50 |
| 未实现端点 | 0（message: Not implemented） |
| 令牌认证不支持 / 参数冲突 / API key 无效（OS） | 41 / 43 / 44 |

### 6.5 模拟目录树（getMusicDirectory）

- 根节点（musicFolderId）→ 子节点 = 艺术家目录（`/艺术家/`）。
- 艺术家目录 → 子节点 = 专辑目录（`/艺术家/专辑/`）。
- 专辑目录 → 子节点 = 曲目 Child。
- 供 DSub 系"文件结构浏览"客户端使用；ID3 路径与目录路径指向同一批实体。

## 7. 流媒体传输（stream / download）

| 项 | 设计 |
| --- | --- |
| Range 支持 | 解析 `Range: bytes=start-end` → 响应 206 + `Content-Range`；整文件 → 200 + `Content-Length`；`Accept-Ranges: bytes` |
| 实现 | `InputStreamResource` + 手动 Range 切片（或 `ResourceHttpRequestHandler` 复用 Spring 能力） |
| MIME | 按 format：mp3→audio/mpeg、flac→audio/flac、m4a→audio/mp4、wav→audio/wav |
| 头 | `Content-Length`、`X-Content-Type-Options: nosniff`、`X-Content-Duration`（时长） |
| 转码参数 | `maxBitRate/format` 接收但忽略（v1 不转码）；`format=raw` 即默认行为 |
| nowPlaying | stream 开始 → 记录 nowPlaying（用户、曲目、时间）；**不**增加 playCount |
| download | 单曲：`Content-Disposition: attachment; filename="<标题>.<ext>"`；专辑/歌单 zip 为可增强 |
| 缺失文件 | 返回 70（数据不存在） |

## 8. 封面缓存

| 项 | 设计 |
| --- | --- |
| 来源 | 内嵌图 > 目录 cover.jpg/folder.jpg（见《音乐管理功能说明》第 6 章） |
| 原图 | 入库时抽取内嵌图存缓存目录（`cover-source/al-<id>.jpg`），避免反复读文件 |
| 缩略图 | `getCoverArt?size=N` → 生成 `cover-cache/al-<id>-<N>.jpg`（最近最少使用 + 容量上限可配置） |
| 尺寸策略 | 原图 / 200px / 64px 按需生成；客户端 size 参数映射到最近档位 |
| 失效 | 扫描更新专辑封面时清除对应缓存 |

## 9. 认证与安全

| 项 | 设计 |
| --- | --- |
| 口令加密 | AES-GCM（随机 IV 前置密文），密钥 = `BIFROST_AUTH_SECRET`（32 字节）或自动生成落 `data/secret.key`（600） |
| Subsonic 令牌验证 | 解密口令 → `md5(password + salt)`（UTF-8，小写 hex）→ 恒定时间比较；salt ≥6 字符 |
| 密码认证 | `p` 明文或 `enc:` hex → 解密口令比对 |
| 管理 REST | HTTP Basic（用户名:密码）或 t/s 令牌；Spring Security 或轻量 Filter（不引入 Security 全家桶，可增强） |
| 初始账号 | 首次启动按配置创建 admin（密码来自环境变量）；已存在则忽略 |
| 传输安全 | 建议反代 HTTPS；`p=enc:` 非加密，仅编码 |
| 安全清单 | 密码永不明文落库/日志；认证失败不区分用户不存在/密码错误（统一 40）；请求参数 URL 编码校验 |
