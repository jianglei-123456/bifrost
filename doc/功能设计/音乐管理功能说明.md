## 1. 概述

音乐管理是 Bifrost **首个交付的媒体垂直**（里程碑 M1），包含：

1. **音乐库管理**：扫描用户目录中的音乐文件，解析标签，构建"艺术家 / 专辑 / 曲目"三层索引，支持封面、播放统计、收藏/评分、歌单。
2. **Subsonic 服务（Syrinx）**：对外提供 Subsonic 兼容协议服务，让 Feishin、DSub、Symfonium、play:Sub、Supersonic 等客户端**直连 Bifrost** 浏览、搜索、播放与管理音乐。
3. **管理契约**：通过 `/api/**` 暴露管理能力（管理端 UI 由另一项目开发，功能规划见第 9 章）。

设计原则：

- **离线优先**：全部元数据来自本地标签解析，不依赖联网刮削。
- **不强制目录结构**：任何松散目录都可建库；标签为主、文件名为兜底。
- **只读解析**：绝不写回/修改源文件标签。
- **中文友好**：中文歌手的拼音首字母索引 v1 内置。

## 2. 支持的格式与标签

### 2.1 容器格式（v1）

| 格式 | 标签标准 | 状态 |
| --- | --- | --- |
| MP3 | ID3v2.3 / ID3v2.4（兼容 ID3v1） | ✅ 支持 |
| FLAC | Vorbis Comment | ✅ 支持 |
| M4A / AAC | MP4 atoms（iTunes 风格） | ✅ 支持 |
| OGG | Vorbis Comment | ⚠️ 可选（视实现进度，不承诺） |
| WAV | 无标签 | ✅ 可入库播放（不参与艺术家/专辑聚合） |
| WMA / APE | — | ❌ 明确不支持（可增强） |

### 2.2 标签字段映射

| 语义 | ID3v2（MP3） | Vorbis（FLAC） | MP4（M4A） |
| --- | --- | --- | --- |
| 标题 | TIT2 | TITLE | ©nam |
| 曲目号 | TRCK | TRACKNUMBER | trkn |
| 碟号 | TPOS | DISCNUMBER | diskn |
| 艺术家 | TPE1 | ARTIST | ©ART |
| 专辑艺术家 | TPE2 | ALBUMARTIST | aART |
| 专辑 | TALB | ALBUM | ©alb |
| 年份 | TDRC / TYER | DATE | ©day |
| 流派 | TCON | GENRE | ©gen |
| 封面 | APIC | METADATA_BLOCK_PICTURE | covr |

字段级规则：

- **albumArtist 缺省回退 track artist**（用于专辑聚合与展示）。
- 年份解析失败置空，不阻塞入库。
- 流派 v1 取**单一值**（多值标签取第一个）。
- 规范化：字符串 trim；专辑聚合键做大小写折叠（见第 4 章）。

### 2.3 解析实现

- 使用 **jaudiotagger**（net.jthink:jaudiotagger:2.0.3）作为标签解析库，位于 `bifrost-core/audio` 包。
- 解析失败的文件：仍可入库（文件名兜底），标记解析错误供统计；不阻塞扫描。

## 3. 扫描与索引流程

### 3.1 触发

| 方式 | 入口 |
| --- | --- |
| 手动（全部） | `POST /api/scan` 或 Subsonic `startScan` |
| 手动（单根） | `POST /api/library-roots/{id}/scan` |
| 定时 | `bifrost.scan.cron`（默认每日 03:00；置空禁用） |

### 3.2 流程

```
遍历库根文件
  ├─ 文件扩展名不在支持列表 → 跳过
  ├─ 指纹（路径+大小+mtime）与库内一致 → 跳过（增量）
  ├─ 新文件 → 解析标签 → 入库（Track）→ 聚合（Artist/Album）
  ├─ 指纹变化 → 重新解析 → 更新记录
  └─ 库内记录的文件消失 → 标记 isAvailable=false
聚合刷新（专辑时长/曲目数、封面、艺术家专辑数）
发布 ScanCompletedEvent（统计：新增/更新/缺失/错误）
```

- 指纹相同即跳过，**不重解析标签**（性能关键）。
- 每库根顺序扫描，全局单扫描互斥，幂等可中断重启。

### 3.3 缺失文件

- 标记 `isAvailable=false`：从 Subsonic 浏览/搜索/歌单对客户端**隐藏**，但保留记录与歌单引用。
- 管理 REST 提供手动清理；自动清理策略为可增强。

## 4. 艺术家 / 专辑 / 曲目聚合规则

### 4.1 全局聚合

- 艺术家、专辑为**全局聚合**实体：同名专辑在不同库根中合并为同一个实体（符合客户端直觉）。
- **曲目记录归属库根**（libraryRootId）；`getIndexes` 可按 musicFolder 过滤。
- 一个曲目同时从属于：1 个专辑（albumId）+ 0..1 个专辑艺术家（Artist）+ 0..1 个曲目艺术家（Artist）。

### 4.2 专辑聚合键

```
专辑键 = normalize(albumArtistName) + "|" + normalize(albumTitle)
normalize = trim + 大小写折叠（lowercase）
```

- albumArtist 缺省 → 用 track artist 参与聚合。
- **多碟合并**：discNo 不同的曲目合并为同一个专辑实体（discNo 默认 1）；碟标题 v1 忽略（可增强）。
- **合辑**：按标签字面值处理（如 "Various Artists" 原样作为 albumArtist，不强制规范化）。
- v1 不做模糊匹配（可增强：编辑专辑归属）。

### 4.3 排序与展示

| 维度 | 规则 |
| --- | --- |
| 艺术家 | 按名称排序；索引分组见第 5 章 |
| 专辑 | 按年份（缺失排后）→ 标题 |
| 曲目 | 按 discNo → trackNo → 文件名 |
| 播放列表 | 按条目 position |

## 5. 索引分组（拼音索引）

- 艺术家索引按**首字母分组**（Subsonic `getIndexes` / `getArtists` 的 index 概念）：

| 字符类型 | 分组 |
| --- | --- |
| 拉丁字母 | A–Z（不区分大小写，归大写组） |
| 中文 | **拼音首字母**（如"周杰伦"→ Z） |
| 其他（日文、韩文、数字、符号等） | `#` |

- 拼音转换使用 **jpinyin**（短语级多音字词典，如"重庆"→ chong；个别字仍可能不准，人工纠错表为可增强）。
- 艺术家实体的 `indexLetter` 在扫描聚合时计算并持久化，查询不实时转换。
- 专辑内曲目排序见 4.3；`getIndexes` 的 `ignoredArticles` 属性 v1 置空（不剥离 "The" 冠词，可增强）。

## 6. 封面策略

| 优先级 | 来源 |
| --- | --- |
| 1 | **内嵌图**（APIC / METADATA_BLOCK_PICTURE / covr），取第一个 |
| 2 | **目录图**：专辑文件所在目录下的 `cover.jpg` / `folder.jpg`（取存在的第一个） |
| 3 | 无封面 | 

- `getCoverArt` 支持 `size` 参数：按需生成缩略图并**缓存**（原图 / 200px / 64px 等，缓存目录 `bifrost.media.cover-cache-dir`，默认 `./data/covers`）。
- 封面归属：专辑实体持有封面（内嵌图来自该专辑首个带图文件）；曲目可回退到所属专辑封面。

## 7. 播放统计、收藏与评分

| 能力 | 规则 |
| --- | --- |
| 播放计数 | `playCount` + `lastPlayed`；**仅 `scrobble(submission=true)` 落库**；`stream` 调用**不**计数（OpenSubsonic 澄清） |
| 正在播放 | `stream` 调用上报 nowPlaying（用户、曲目、开始时间）；`getNowPlaying` 返回 |
| 收藏 | `starred`（曲目/专辑/艺术家三态）；`star/unstar`（Subsonic）、`/api/starred`（管理 REST） |
| 评分 | `rating` 1–5（0=取消）；`setRating`（Subsonic）、`/api/rating`（管理 REST） |

## 8. Subsonic 服务能力（Syrinx）

### 8.1 协议基线

- **线协议基线：Subsonic API 1.16.1**（REST/XML/JSON、`u/t/s/v/c/f` 参数、令牌认证 `t=md5(password+salt)`）。
- **OpenSubsonic 合规**：响应信封携带 `openSubsonic=true`、`type=Bifrost`、`serverVersion`；实现免认证 `getOpenSubsonicExtensions`；支持错误码 41–44；遵循 OS 澄清（search3 空查询返回全部、stream 不计数等）。
- 挂载路径：`/rest/<method>.view`；默认 XML，`f=json` 切换。
- 认证失败：`HTTP 200 + status=failed + error 40`（非 HTTP 401）。
- 未实现端点：返回 `status=failed + error 0`（未实现），并在下表标注。

### 8.2 端点能力矩阵（v1）

| 分类 | 端点 | 实现 | 说明 |
| --- | --- | --- | --- |

| Browsing | `getMusicFolders` | ✅ | 输出库根列表 |

| Browsing | `getMusicDirectory` | ✅ | **模拟目录树**：`/艺术家/专辑/01 - 标题.mp3`（兼容 DSub 系文件浏览） |

> 端点响应 XML/JSON 结构与字段详见《Subsonic_API_参考》附录。

### 8.3 ID 方案

- 实体 ID 为**带字母前缀的字符串**：`ar-<数字id>`（艺术家）、`al-<数字id>`（专辑）、`tr-<数字id>`（曲目）、`pl-<数字id>`（歌单）。
- 前缀规避"客户端把 ID 强转整数"的坑；数字部分为数据库主键。

### 8.4 客户端兼容矩阵（v1 目标）

| 客户端 | 平台 | 兼容要点 |
| --- | --- | --- |
| Feishin / Sonixd | 桌面 | 走 ID3 路径（getArtists/getAlbumList2/search3）、令牌认证、索取 OS 扩展 → 目标首选验证客户端 |
| DSub | Android | 老牌，令牌认证 + 密码认证、文件结构浏览（getMusicDirectory）→ 验证模拟目录树 |
| Symfonium | Android | 兼容性要求严格、OS 参与方 → 用其 API 指南自检 |
| play:Sub | Android | 付费客户端，常规端点 |
| Supersonic | 桌面 | OS 支持 |
| Sublime Music | Linux | 常规端点 |
| Jam / iSub / OutPlayer / Ultrasonic / Soundwave / Substreamer | iOS/Android | 常规端点；Substreamer 默认令牌认证、有 Legacy auth 开关 |

## 9. 管理端功能规划（供 Dashboard 项目）

> 管理端前端（Vue Dashboard）在**另一独立项目**开发，以下为功能规划与对应 `/api/**` 契约，作为该项目的输入。

| 功能模块 | 功能点 | 对应 REST |
| --- | --- | --- |
| 系统总览 | 媒体库统计（艺术家/专辑/曲目数、总时长、库根数）；最近扫描状态 | `/api/scan/status`、浏览端点汇总 |
| 库根管理 | 列表/新增/编辑/启停/删除库根；触发单根扫描 | `/api/library-roots*` |
| 扫描管理 | 触发全量扫描；查看扫描进度与上次统计 | `/api/scan`、`/api/scan/status` |
| 媒体浏览 | 艺术家/专辑/曲目列表与详情（含封面、播放统计、评分、收藏） | `/api/artists|albums|tracks*` |
| 搜索 | 全局搜索（艺术家/专辑/曲目） | `/api/search?q=` |
| 歌单管理 | 歌单 CRUD、条目增删与排序 | `/api/playlists*` |
| 收藏与评分 | 收藏/取消收藏、设置评分 | `/api/starred`、`/api/rating` |
| 账号设置 | 查看当前账号、修改密码 | `/api/user`、`/api/user/password` |
| 系统信息 | 版本、健康检查 | `/api/ping` |

> 契约细节（请求/响应示例）由管理 REST 设计补充；Dashboard 项目可独立推进，仅依赖 `/api/**`。
